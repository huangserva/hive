OpenPI 有没有给 Pi worker 增加“记忆”？

一句话结论：没有跨 Session 的长期记忆；OpenPI 的“连续性”是把工作状态绑定在 Pi Session / branch 的持久历史与生命周期上。

Tasks、Goal、Context Pivot 和 Session Browser 让同一个 Pi Session 更容易持续工作、恢复和切阶段；pi-intercom 让多个顶层 Session 互发消息。它们都不是 memory 文件、向量库或知识库，也不会让新 Session 自动回忆旧任务。

同一 Session：会记得进程重启后 /resume 同一 Session，Tasks 与 Goal 会从 Session branch 的自定义 entries 恢复。
切阶段：保留简报Context Pivot 用一份自包含 brief 替换活跃上下文；旧记录仍在原始 Session 历史里，但不会自动回到模型上下文。
新 Session：不会记得新开 Session 没有旧 Session 的 Tasks、Goal 或知识；Session Browser 只能预览并切换回旧 Session。

为什么它不算“长期记忆”

README 把这些能力称为“连续工作，而不是堆 Context”：Tasks 维护当前批次意图，Goal 维持目标到终态，Context Pivot 用简报进入下一阶段，Sessions 搜索/预览/切换。其权威事实仍是文件、Git、测试、产物和用户反馈。源码中没有发现跨 Session 的 memory 文件、embedding、向量库、知识索引或新 Session 自动召回路径。

证据：README.md:373-384、627、635-637；docs/decisions/0002-native-skill-lifecycle.md:12-25、40-44。

对 Hive 派出的 Pi worker 意味着什么

场景装 OpenPI 后多了什么仍然没有什么
Hive 恢复同一个 Pi Session结构化 Tasks、可续跑 Goal、目标预算/用量、主动阶段简报、方便查找并切回旧 Session。不会把历史自动提炼成可跨任务检索的知识。
Hive 每次派活都新建 Pi Session本次任务内的工作组织能力。上一任务的 Tasks、Goal、偏好、经验和修复结论都不会自动出现。
多个顶层 Pi 同时协作可选 pi-intercom 提供直接消息通道；已送达消息留在各自 Session 历史。没有共享、耐久、可检索的团队记忆；离线 mailbox 也不耐 broker 重启。

最省事的跨任务记忆接法：Hive + MemOS CLI

  1. 派活开始：由 Hive worker 启动模板执行一次 memos search "<用户原始任务>" --format agent --detail simple，把结果作为背景上下文注入新 Pi Session。
  2. 任务结束：只有形成经验证、跨任务仍有用的结论时，执行一次 memos add；保存用户长期偏好、架构决议、确认过的根因与修复、可复用 SOP。
  3. 职责分开：Hive 的任务账本和代码仓库继续做操作事实来源；OpenPI Tasks / Goal 管当前 Session 的执行状态；MemOS 管跨 Session 的长期经验。

第一版无需修改 OpenPI：把 search/add 约束放进 Hive 的 Pi worker 启动与收尾提示即可。不要把 secret、原始聊天、临时进度或未经验证的猜测写进 MemOS。
